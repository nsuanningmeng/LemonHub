## 修复的迁移风险

1. **宽文本及字符集可能被缩窄。** 旧 `migrateTokenModelLimitsToText` 对非 TEXT 类型直接执行裸 `MODIFY ... TEXT`。在真实 MySQL 5.7 非严格模式下，70,000 字节 MEDIUMTEXT 会被截断；显式 utf8mb4 列回落到表默认 utf8 时，emoji 会被替换。修复先核对真实列/表排序规则，并对 MEDIUMTEXT/LONGTEXT 检查字节长度。不能无损转换就报错停止；普通 TEXT、CHAR/VARCHAR/TINYTEXT 不扫描全部 token 行。
2. **已是 DECIMAL/NUMERIC 不等于转换安全。** 旧代码对任何 decimal/numeric 提前返回；GORM 后续因默认值或可空性调整，仍可能将宽类型重写为 decimal(10,6)。真实测试中 `1.00000000000000000001` 被舍入为 `1.000000`，严格模式也不能防止此类小数舍入。现在提前检查范围、NULL 和小数精度，并从数据库读取精确文本进行 decimal 比较，不先转 float64。数据库元数据查询失败也停止迁移。

两类保护同时覆盖串行 `migrateDB()` 和并行 `migrateDBFast()` 的前置调用；异常被拒绝时，测试核对原值及原表定义没有改变。现有目标业务表定义、钱包数值域和凭证格式未调整。非标准结构可能主动拒绝启动；应先保留备份并人工确认处理，不能删除数据库或用截断替代修复。

MySQL DDL 不是整个迁移的单一事务。上述检查也不是跨进程迁移锁：升级前需停止旧应用写入，以一个迁移主节点完成升级后再扩容。不要依赖多个默认 master 同时迁移来保证安全。

## MySQL 容器升级演练

使用独立网络、容器、命名卷和带固定前缀的临时数据库；没有使用生产数据库，也没有操作环境中原有的 MySQL 容器。

- 旧应用采用官方 `ghcr.io/nsuanningmeng/lemonhub:v0.4.43`，镜像 manifest digest 为 `sha256:2d6bf74c150bc3233ff616b3a5caff3911c71fb31fe53071a2874f84efcc6277`。
- 候选测试镜像复用该运行时，只替换以最终源码构建的 `/new-api`；Dockerfile 运行时未改变。二进制使用 Go 1.26.8、Linux/amd64、CGO=0，包含最终前端产物及迁移保护，版本为 v0.4.44，SHA256 为 `a0da287fbfc817db0a0ef70753b9b9c8d743954ee41f06c1846ce4ceb69a46b4`。正式发布镜像仍由 GitHub Actions 按发布提交重新构建。
- 由旧应用真实启动创建 schema，停止应用后写入 49 条显式哨兵，再用旧应用复启验证测试数据本身兼容。最终快照覆盖 **43 张业务表、56 行、550 列定义**，包括旧应用产生的配置和权限记录。
- 数据包括主站/子站同名用户、软删除记录、接近钱包上限的余额、50 亿 token 额度、凭证、支付/订阅订单、任务账务、身份/会话、日志、站点资金、自定义权限，以及 NULL、false、中文/emoji 和原始 JSON。
- 分别执行新版应用启动、应用容器再次重建、MySQL 容器停止删除后复用原命名卷重建、`mysqldump` 恢复到全新隔离库，并比较数据及结构。

比较没有忽略整个权限或账务表。明确的例外仅为：启动动态元数据的 3 张表单独记录；原有权限初始化会重建的 3 条内置 admin policy 允许其内部行 ID 变化，但权限元组必须相同，自定义权限全部字段严格保留；幂等插入可能推进 AUTO_INCREMENT，MySQL 5.7 重启也可能按现存最大 ID 重算该计数，但表结构及业务行保持一致，后续 ID 不会与现存行冲突。后台既有的过期预消费记录清理仍生效，因此保留性哨兵使用未过期记录。

MySQL 8.0/8.4 的备份恢复会在 SHOW CREATE 文本中增加冗余的 `CHARACTER SET utf8mb4` 声明。初次按 DDL 原文字节比较因而失败，数据未变；进一步核对完整有效列元数据、排序规则、索引和表属性均相同后，只允许这一冗余文本差异。原始失败与修正后的对比证据均保留，没有放宽真实字符集、金额或其他字段比较。

本结论限于上述应用升级、同版本引擎和同一持久化卷。本轮日志与主业务使用同一数据库，未演练独立 `LOG_SQL_DSN`。不覆盖线上实际卷绑定、生产数据量、断电/磁盘损坏、多主同时迁移或 MySQL 引擎跨大版本升级。实际部署步骤见 [MySQL 容器升级说明](mysql-container-upgrade-safety.md)。
