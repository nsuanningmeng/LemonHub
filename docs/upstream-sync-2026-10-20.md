## 兼容与数据边界

- 没有新增或替换数据库模型、DDL、启动迁移，不重写历史余额、账单、订单、渠道凭据或已有定价。渠道优先级仅在管理员明确操作后同事务更新 channels 与 abilities；只读预览不落库。
- 历史 NULL 优先级可无损保留和撤销；超出 JavaScript 安全整数范围的历史优先级拒绝拖动，不通过重编号“修复”原值。
- 新通知字段由旧设置扩展而来；旧客户端未发送的新开关保持已存状态，语言、侧栏、营销退订和管理员控制的正文记录字段继续保留。原设置 JSON 损坏时拒绝覆盖。
- 低余额提醒继续采用“低于阈值 + 配置限流”，不声称并发扣费下每次越线严格提醒一次。订阅和钱包结算没有因通知功能替换实现。
- 默认邮件仍是 SMTP；Resend 启用前校验完整最终配置。发送失败不切回 SMTP，避免不确定投递结果引起重复验证码/邮件；错误不会输出密钥、验证码或上游响应正文。
- Dockerfile、Compose 服务名、镜像引用和数据挂载保持原部署约定。仓库默认 Compose 使用 PostgreSQL，实际 MySQL 部署应继续使用自己的原配置，不能以仓库示例覆盖。

## 分批代码审查

每个功能批次实现后检查变更、调用链、本地合同及对应测试，再纳入同步分支。独立审查覆盖通知配置/鉴权/资金路径、AWS 请求与签名、协议转换、DeepSeek 新端点计费、前端状态/权限/异步错误、渠道事务与数据库兼容、容器监控、启动和部署流程。

本轮审查已促成以下修正：

- CPU 父级用量不能除以子进程亲和核数，否则父级其他进程正常占用也会误触发 503。
- cgroup v1 CPU 与 cpuacct 归属不同不能通过同名目录猜测配对，无法确认时回退。
- 通知设置损坏 JSON 不得退回默认值并覆盖原始配置；新通知不能绕过主站管理员边界。
- 已撤销 `ChannelRead` 的管理员不能通过订阅通知继续读取渠道详情；渠道和上游模型通知发送前都复用既有权限检查。
- Resend 配置不能依赖单个节点的缓存进行预检；改为事务内锁定数据库完整配置组，拒绝使活动供应商失效的修改，并验证新配置首次写入及多节点竞争。
- 已翻译的余额通知正文不能再次作为 `fmt.Sprintf` 模板解析；Webhook 保留原 `values` 字段并仅替换约定占位符，避免百分号和 URL 被破坏。
- 低余额并发越线语义不能用请求前快照保证，保留现有可靠限流语义。
- DeepSeek 有实际结果的按次调用需要明确的本地计费标记，不能落入旧“零 token/零工具用量不扣费”的保护分支；空/错误结果仍退款。
- DeepSeek 工具错误可能回显查询或网页正文；错误处理仅保留状态，消费与运行日志不记录这些正文。
- 邮件配置保存失败必须显示后端原因并保留尚未提交的凭据草稿，不能因刷新配置而丢失可重试内容。渠道表格/卡片视图切换补齐可访问名称。
