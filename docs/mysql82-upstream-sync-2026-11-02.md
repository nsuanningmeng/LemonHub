## 数据范围与严格比较

两条基线使用各自独立的 MySQL 容器和命名卷，主库与日志库分开连接。均包含 **53 表、66 行，所有表非空**：主库 51 表、64 行，独立日志库 2 表、2 行。入口旧版本共 681 列；原主分支基线及最终版本共 683 列。

夹具包含账户、API Token、密码哈希、会话、身份绑定、自定义权限、渠道配置、充值与订阅、结算回执、任务账本、统计、工单和附件，以及奖励活动、已领取/待领取奖励、持续发放状态、候选领取人和主/日志库的持久化奖励事件。包含 NULL、Unicode、二进制、精确小数和超过 int32 的金额/计数；账户及 Token 剩余额度均为 `5000000007`。数据目录和附件目录均放置文件哨兵。

比较全部已有行的全部字段，并检查列顺序、类型、默认值、NULL 属性、字符集/排序规则、索引及前缀长度、表引擎/行格式/属性、自增值和 `SHOW CREATE TABLE`。二进制保留十六进制表示，整数不经过浮点转换。表数或行数相同不作为通过依据。

仅允许以下已审查差异：

1. **仅入口 `4751f44e3` 路径**：主库和独立日志库的 `logs` 各增加一个 `is_retry tinyint(1) DEFAULT NULL` 字段，追加到原列之后；每条历史记录的新字段严格为 SQL NULL。移除这两个新增字段后，全部原行、原列、索引和有效表结构严格一致。该改动来自任务开始后拉取的原 LemonHub 主分支更新，不是本轮上游选择性移植新增的数据库结构。`012a5f856` 路径没有结构变化。
2. 当前测试节点的运行信息、启动时间和心跳可以更新；该节点名称及创建时间、其他节点的全部字段必须保留。
3. 仅三条精确的内置权限元组 `(p, role:admin, channel, read/operate/write, allow, '', '')` 允许重建数值 ID，权限内容不变；所有自定义规则逐字段保留。`casbin_rule`、`authz_roles`、`external_identity_claims` 的自增值只允许单调增加。
4. 备份恢复仅允许等价的显式默认字符集声明差异，并同时严格核对全部有效列字符集/排序规则与其他元数据；不放宽实际字符集、类型或数据比较。

## 启动信号问题的复现与修复验证

旧 `012a5f856` 应用在 HTTP 已可用之后才等待 100 毫秒、打印启动信息并注册 SIGTERM。测试曾在 `/api/status` 首次 200 后立即停止容器，复现退出码 2、没有正常排空日志。该次空闲夹具的前后业务数据比较仍通过，**没有把这个生命周期缺陷宣称为已观察到的数据丢失**。原始日志、退出状态和数据比较分别保留于 `baseline-early-sigterm-app.log`、`baseline-early-sigterm-state.json`、`baseline-early-sigterm-data-comparison.json`。

本轮将信号注册提前到初始化及 HTTP 开放之前。最终候选在两条路径中分别于首次健康响应后约 **20.4 毫秒、14.6 毫秒** 发起 Docker 停止，均输出收到 SIGTERM、正常排空和 `server exited`，退出码为 0，全部业务快照保留。旧应用正式基线则等待完整启动日志后再正常停止，不用旧竞态污染迁移验收。

准备阶段还发现第一份合成夹具缺少已有自定义 OAuth 绑定对应的 claim。旧应用按原有迁移补齐一行，严格比较器正确拒绝该变化；核实旧 claim 全部保留后，以规范化后的旧库建立正式基线。入口旧库的夹具直接包含这条 claim。初次失败及修正证据保留，没有为候选新增宽泛例外。
