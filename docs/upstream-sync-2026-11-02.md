## 取消的大范围改动

`70e6af642` 修改 63 个文件，包含参数覆盖条件/merge/prune、计费 param(path)、Claude schema、AWS 透传、图像 SSE、媒体 base64，以及被排除的插件和本地缺失的 WebSocket 分支。其核心从 gjson/sjson 与字节切片切换为新的 ojson.Doc，并非可独立启用的性能选项。

当前本地已有原始 JSON、用量、错误、审计与独立 relaykit 合同，直接替换无法据此保证等价。审查还发现该提交对重复 JSON 成员的删除使用不一致：部分路径循环删除同名键，视频遮罩使用单次 Delete；该新引擎下的结果未经本轮运行验证。按本次兼容性要求取消整体替换，保留已有引擎和独立正则缓存优化。这不是数据库破坏结论，也不表示该改动永远无法适配。

## 数据与运行行为边界

- 相对于 `012a5f856`，本轮不修改 model、数据库迁移、表结构、现有价格或历史账单，不新增插件表。入口 `4751f44e3` 到本仓库新基线之间已有日志 `is_retry` 可空列变更，单独纳入旧版本升级验证。
- 缓存写入别名和 xAI 明细修正会让**新请求**按已有缓存价格正确结算，不重算历史余额。
- 默认任务超时从 24 小时延长到 72 小时；显式 TASK_TIMEOUT_MINUTES 不变。不会重新打开历史失败任务。
- zstd 历史窗口超过 8 MiB 的请求现在会返回 413，即使解压后正文小于更大的请求体上限；这是本轮引入的明确兼容边界。
- Docker 仅更新前端构建工具阶段；运行时、Compose 服务/项目身份、数据库连接、数据卷及停机宽限保持原约定。
- 实际生产仍应保留原 MySQL 8.2 数据卷、库名、DSN 和加密/会话密钥，仅替换应用镜像。参见 [只读升级预检](mysql-compose-upgrade-preflight.md)。
