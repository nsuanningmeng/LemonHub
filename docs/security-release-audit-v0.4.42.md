日期：2026-09-25。基线：v0.4.41（`e915daf4f`）。本版本新增控制台公告横幅，并处理审查中确认的既有安全问题。

- 独立审查公开公告接口、配置写入权限、Markdown/HTML 净化、OAuth 登录/绑定与会话边界、桌面启动及发布工作流。
- 复核个人密钥、渠道敏感密钥、日志、工单和视频的路由权限及所有权；附件路径限制；媒体、通知及 Webhook 的 SSRF 防护。定向权限、路径和 SSRF 回归通过。

## 公告横幅的安全边界

- 数据继续来自公开 `/api/status` 的全站公告；写入 `/api/option/` 仍由服务端 RootAuth 保护。横幅不新增接口、凭据存储或外部网络目的地。
- 摘要作为 React 文本节点输出，去标签正则只是展示处理，不作为安全过滤器；正文与附加说明复用现有 Markdown → DOMPurify 链路，外链保留 `noopener noreferrer`。
- 自动滚动不写入已读状态。横幅不依赖同一浏览器中共享的历史通知已读缓存，不会因切换账号而隐藏公告。
- 测试通过真实横幅打开详情，验证脚本、事件属性和可执行 URL 被清理，同时保留正常 HTTPS 链接及安全外链属性。

## 确认并修复的问题

- OAuth 登录 state 缺少发起浏览器绑定，其他浏览器持有相同 state 和授权码时仍会进入兑换流程。修复前确定性回归得到 HTTP 200 且提供商被调用；应为 HTTP 403 且不得兑换授权码。
- 修复为独立的短期浏览器 Cookie 与服务端 HMAC 验证，验证发生在提供商兑换前。HTTPS 模式使用 `__Host-` Cookie 限制跨子域注入；账户绑定仍检查原用户与原登录 Session。
- 微信与 Telegram 的非标准登录入口也要求浏览器绑定的 flow；前端仅在用户发起登录操作时创建，通过 `X-OAuth-State` 单独传递，Telegram 签名参数不变。微信旧回调页只能使用已有 state，不能自动创建新 flow；Telegram assertion 与 flow 在同一事务内消费以保留重放保护。
- 密码登录接受跨站 `text/plain` 表单中的 JSON，真实路由回归确认会签发 Refresh Cookie 并创建会话。新增 JSON/来源校验，保护密码登录、2FA 登录、Passkey 登录完成及首次初始化 POST；拒绝非 JSON 表单和不可信显式来源。无 Origin/Referer 的 JSON 客户端仍可使用；OAuth 的提供商 GET 回跳继续使用浏览器绑定验证。
- 桌面版本地服务及可选 pprof 的监听边界在本版本收紧；普通 API 网关保持既有对外访问用途。
- 联系我们页面的自定义 HTML 曾直接插入 DOM，未清除事件属性及可执行链接。配置写入需要 Root 权限，但从外部粘贴的恶意 HTML 仍可能影响访客。本次改为复用经过 DOMPurify 的 RichContent，并移除 URL 嵌入的 `allow-same-origin` 权限；两个回归用例均先失败后通过。

## 部署边界

- 生产 HTTPS 必须使用 `SESSION_COOKIE_SECURE=true` 才能获得 `__Host-` Cookie 的跨子域注入防护。`false` 模式仅用于可信本地 HTTP；普通名称 Cookie 不能防止不可信兄弟子域的 Domain Cookie 注入。
- 发起登录与提供商回调必须使用相同主机。GitHub/LinuxDO 等使用预设回调地址时，应从规范主机发起，不能放宽 Cookie Domain。升级前未绑定浏览器的旧 flow 需要重新发起。
- 登录与初始化 POST 客户端必须明确发送 `Content-Type: application/json`。反向代理终止 HTTPS 时，按认证部署文档设置精确的 `SESSION_COOKIE_TRUSTED_URL`；不会信任客户端提供的 Forwarded 头。仅非 secure 模式下、浏览器与后端均为 HTTP 回环地址的开发代理允许跨端口，远端/LAN 跨源开发需使用同源代理。
- 普通服务可设置 `BIND_ADDRESS`（仅主机，不含端口）；未配置仍监听所有网卡。Electron 生产子进程强制 `127.0.0.1`。pprof 默认关闭；启用后默认 `127.0.0.1:8005`，`PPROF_LISTEN_ADDRESS` 是显式覆盖，远程开放仍需部署方访问控制。
- 桌面初始化风险通过真实 `PostSetup` + 内存 SQLite 的无监听 `httptest` 重现，结合静态监听链路确认；未做局域网连通性实测。修复后使用真实回环监听验证 HTTP 行为，并执行 Electron 实际启动代码检查子进程环境。
- 代理/Worker 的最终 DNS 与连接由远端负责，本次没有验证实际部署；既有 `/mj/image/:id` 公开图片链接未变更。本次不能替代全部提供商适配器的逐项协议审查。
