# v0.4.40 钱包与支付安全审查

日期：2026-09-23。基线：v0.4.39（`c111d2658`）。本次包含大额充值修复，以及随后安全审查发现的金额、缓存并发和浏览器支付跳转问题。

## 范围与方法

- 全仓规则扫描覆盖 2128 个源文件；人工复核 Critical/High 命中，并重点追踪充值报价、创建订单、支付回调、数据库授信、缓存同步、任务结算和退款回滚。
- 独立复核后端金额契约、钱包/令牌缓存并发、前端报价状态与危险跳转；使用确定性回归复现已确认的问题，不进行真实扣款。
- 使用 Go 官方漏洞库分析 Windows/amd64、Linux/amd64 下根模块与独立 relaykit 的可达调用；检查前端和桌面锁定依赖。
- 对旧 INT 用户表进行真实数据库升级、重复迁移及数据保留验证。测试只使用独立临时数据库；没有修改生产数据库、余额或支付配置。

## 确认并修复的问题

| 问题 | 修复与验证边界 |
| --- | --- |
| 大额充值及已有大额钱包被错误拦截 | 钱包使用 BIGINT 与 `2^53-1` 精确整数上限，充值使用严格 decimal 转换；单次 API 计费仍受 int32 限制。回归覆盖低余额及已有约 `10^15` 额度账户、30000 充值和边界拒绝。 |
| 报价失败显示 0 且允许继续支付 | 错误状态与有效金额分离，过期响应失效；报价异常禁止确认，展示后端具体原因。 |
| 任务结算继续使用 int32 钱包总量 | 修正任务资金和累计消耗边界；保留单次目标额度、差额和请求计数保护。 |
| 缓存重建后重复授信（P1） | DB 提交前捕获 Redis 余额 generation，只向同代缓存补增量。覆盖钱包、令牌、充值、兑换、签到、邀请奖励、任务退款及退款回滚；重建缓存和并发扣费都有确定性回归。令牌保留原 64 位域，不套用钱包上限。 |
| Stripe 报价、Checkout 数量与到账额度不一致（P1） | 统一充值单位及折扣数量，严格核验网关原始 decimal 单价和币种精度；使用同一份 Price ID/API key 快照下单。旧订单仍按原记录结算。 |
| 非有限金额配置及无法到账的订单 | 拒绝 NaN/Inf/无效倍率，避免 decimal panic 或无效金额进入支付；Creem/Waffo 下单校验必要回调配置。有限非正预设折扣保留原有“不打折”语义。 |
| 不受限的浏览器支付跳转 | 拒绝脚本、data、相对和带凭据地址；Epay 仅 HTTPS，新窗口隔离 opener；签名字段按 input value 写入。 |
| Creem 人工补单重复换算原始额度 | 与回调保持同一单位，防止再次乘以 QuotaPerUnit；保留订单幂等及到账事务保护。 |

所有授信在结算时再次原子校验容量；报价检查不能代替最终额度检查。超出容量的订单不能部分到账或饱和截断。

## 扫描结果解释

- 规则扫描的 7 个 Critical、8 个 High 命中经人工核对为固定 SQL、受控测试表名、测试密码、PEM 边界标记或已由 DOMPurify 处理的渲染点，不按标签直接认定漏洞。
- 根模块 Windows/Linux 扫描均报告可达漏洞 0、导入包漏洞 0；仍有 1 项所需模块内但未导入的漏洞提示。与上次审查相同，为废弃 `x/crypto/openpgp` 的 GO-2026-5932，不能描述为已经修复。relaykit 两个平台均无漏洞报告。
- `bun audit --json` 返回 `{}`，桌面 `npm audit --json` 报告已知漏洞 0。本次未修改依赖版本。
- 钱包目录未改动文件存在 6 个既有 lint 错误；本次修改及新增的前端文件 lint 通过。未宣称全仓 lint 通过。

- 前端 58 个文件、397 项测试通过；类型检查、生产构建、1183 文件格式检查及本次变更 lint 通过。首次高并发全量运行有一个模型定价测试超过 5 秒；未改测试或放宽超时，以两个 worker 重跑全量通过。

- Go 1.26.8 下根模块全量测试通过（35 个有测试包、54 个无测试包），独立 relaykit 的 7 个有测试包通过；根模块及 relaykit 的 vet/build、`git diff --check` 均通过。CI 在 Linux 上再次验证同一提交。

## 升级与限制

- 升级前备份数据库，保留原数据卷。先完成后端迁移，并统一升级多实例再开放充值，避免旧节点继续使用旧额度及缓存逻辑；大额到账后不要把 BIGINT 降回 INT。
- 支付服务商自身限额仍然生效。Stripe 固定 Price 无法表达的非整数数量明确拒绝；未使用真实支付验证外部商户账户额度或风控。
- 缓存代际变化可能保守地暂留较低余额，等待正常刷新；不会补入无法证明尚未反映的额度。未实测生产规模迁移耗时、故障断电恢复或跨数据库引擎升级。
- 自动扫描、代码复核与回归覆盖已知边界，不等于不存在未知漏洞。发布成功也不代表生产站点已完成部署。
