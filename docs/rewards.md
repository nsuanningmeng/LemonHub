# 奖励中心

管理员通过侧边栏「奖励中心」（`/reward-campaigns`）创建活动；用户通过「我的奖励」（`/rewards`）领取。

## 发放

1. 输入活动名称、说明，选择「奖励金」或「拼手气红包」。奖励金设置每人固定金额；红包设置每人随机金额的上下限。输入金额单位为 USD，后台转换为现有钱包的整数额度。
2. 选择筛选时段和发放对象：成功充值用户、成功调用用户、成功充值用户和成功调用用户（交集），或成功充值用户或成功调用用户（并集）。「和」要求两类记录都发生在所选时段内，「或」满足任意一类即可。界面显示浏览器本地时区，范围包含开始时间、不包含结束时间。
3. 设置奖励有效天数（默认 7 天，可输入 1–3650 的整数），奖励金和红包均适用。从实际发放时间起按每 24 小时为一天计算，筛选时段不会影响到期时间。预览和确认时显示有效期，发放记录显示实际到期时间。
4. 预览符合条件人数和总预算，确认后发放。若人数在预览后变化，需要重新预览。

所有发放对象都必须是**已启用、未删除的主站用户**，停用用户不参与预览和发放；预览后用户停用导致人数变化时，需要重新预览。充值按支付完成时间筛选，仅包含成功且没有退款扣回的订单；调用按消费日志时间筛选，错误日志不计入。同一用户同时满足两种条件也只收到一份奖励。调用记录使用项目配置的日志数据库；已清理或未记录的调用不参与筛选。

每次活动保存当时的收件人名单，后续充值或调用不会追加收件人。单次最多支持 100,000 个候选用户，最大奖励预算不得超过钱包安全整数上限。创建请求使用 `request_id` 防止网络重试或重复提交产生重复发放。

发放记录按活动显示**已领取人数**和**共计已领取金额**，只统计领取成功且已入账的奖励。红包按实际抽中金额累计，不使用配置上限或预算估算；重复领取不会重复计数。用户领取后再被停用或删除，其历史领取仍保留在统计中。记录页每 30 秒自动更新，重新切回窗口时也会刷新。

## 领取

- 登录后发现待领取奖励会自动弹窗；已在线的用户每 30 秒检查新奖励，侧边栏同步显示待领取数量。
- 「稍后领取」暂缓当前已知奖励在本浏览器会话中的自动提醒；用户仍可随时进入「我的奖励」手动领取。新发放的奖励仍会提醒。
- 固定奖励领取后直接加入账户余额；红包在领取时由服务端在配置范围内抽取整数额度，包含上下限，领取前不产生中奖金额。
- 领取状态、中奖金额和钱包加款在同一数据库事务中提交。重复领取返回之前的结果；事务失败不改变余额或奖励状态。提交后同步现有余额缓存，领取明细作为主库内的持久记录，并附加系统日志。
- 红包底部以小字显示到期时间，使用浏览器本地时间；待领取卡片也显示截止时间。
- 到期时刻起不能再领取，服务端在领取事务内校验，过期不会抽奖入账，也不会增加已领取人数或金额。过期奖励不计入待领取数量、不再自动提醒，可在历史记录中查看。
- 领取有效时刻以事务内的服务端校验为准：取得锁后、确定金额后以及写入钱包后均检查截止时间，最后一次校验必须严格早于 `expires_at` 才允许提交。若钱包写入后已到期，奖励记录和余额一起回滚；不以网络响应或物理 COMMIT 完成的时刻判定有效期。
- 已成功领取的奖励不受后续到期影响，重复请求仍返回之前的结果，不会重复入账。发放请求重试也不会延长原到期时间。

## 接入与升级

服务启动迁移会创建或更新 `reward_campaigns`、`user_rewards` 两张表，串行和并行迁移入口均已注册。新增 `expires_at` 字段默认为 0，升级前已发放的奖励保持原来的无期限行为；新创建活动必须提交有效天数。沿用现有登录、管理员鉴权、限流与余额展示配置。

| 接口 | 用途 |
| --- | --- |
| `GET /api/rewards/summary` | 当前用户待领取数量及固定奖励总额度 |
| `GET /api/rewards` | 当前用户分页奖励；可按 `status`（`pending`、`claimed`、`expired`）、`type` 筛选 |
| `POST /api/rewards/:id/claim` | 领取本人奖励，返回奖励结果及最新钱包额度 |
| `POST /api/reward-campaigns/preview` | 管理员预览符合条件人数 |
| `POST /api/reward-campaigns` | 管理员创建活动并发放；客户端传预览人数 `expected_recipient_count` 和有效天数 `expires_in_days` |
| `GET /api/reward-campaigns` | 管理员分页查看发放记录，含 `claimed_count` 已领取人数、`claimed_quota` 已领取总额度 |

列表分页使用 `p`、`page_size`。API 金额字段均为钱包整数额度，时间为 Unix 秒，活动及用户奖励均返回 `expires_at`。到期状态按服务端当前时间计算，不依赖定时任务。管理员及个人设置中均可控制对应侧边栏入口的显示。

## 数据库回归验证

MySQL 专项测试使用 `MYSQL_REWARD_TEST_DSN` 指向**新建、空的** `lemonhub_rewards_test_*` 数据库；测试会拒绝其他库名或非空库，只清理测试创建的表。不要使用应用数据库或现有数据卷。

```sh
go test ./model -run '^(TestMySQLReward.*|TestRewardClaimExpiryBoundaries)$' -count=1 -v
```

覆盖升级前奖励表的完整数据保留、两次迁移幂等、旧零值有效期、不同 MySQL 连接竞争领取及重复发放，以及领取事务跨截止时刻的余额与统计回滚。时间边界测试只控制外部时钟和抽奖熵，数据库事务真实执行，不依赖睡眠或概率性的并发压力。
