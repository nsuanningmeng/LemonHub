## 安全与兼容审查

- 未修改数据库模型、字段、索引、启动迁移、钱包、身份 claim 事务、依赖版本或历史账单；
  保留原有按 `site_id` 隔离的数据访问和授权。
- 请求真实 usage 后，未来请求的计费 token 可能从估算改为上游实值；这是本项修复的预期效果，
  不等于价格调整或历史余额重算。原用量处理、计费饱和保护、预扣与结算链保持不变。
- 独立审查发现 Gemini 转换原本会丢弃仅含 usage 的尾帧。作为本批必要兼容适配，保留该帧，
  让客户端最终用量与服务端收到的实际用量一致；纯空首帧继续过滤。
- OAuth 前端不新增凭据存储或后端请求权限；保留子站回调及 Telegram 字段。
  原逐项保存 option 的非原子语义未改变。
- 全仓库规则扫描覆盖 2,111 个文件，15 条 critical/high 命中经人工复核均未确认实际漏洞，
  包括固定 SQL、测试夹具、PEM 标记和清洗后的 HTML。规则扫描只作为辅助，不代表渗透测试或完整供应链审计。
- 既有 GitHub 用户名形式旧绑定的归属校验问题没有由本批修复；下一批单独适配，
  必须保留本项目子站作用域和用户/身份记录的同事务更新。

## MySQL 升级迁移验证

使用全新临时数据目录和专用测试库，分别运行 MySQL 5.7.44、8.0.44。两个版本均通过：

1. 五组仓库迁移/身份回归，无跳过：从旧 rc25 结构执行真实 `migrateDB()` 并重复运行，
   核对存量数据、子站配置、钱包及历史流水、返佣/提现记录、身份排序规则冲突与索引。
2. Token 额度由 INT 扩为 BIGINT 后，旧字段保留，50 亿余额和 40 亿已用值正常读写，
   重复迁移不会缩回；超长充值状态在 DDL 前拒绝，正常状态保持原值。
3. 六种内置身份解绑的跨子站事务契约：两个子站可持有相同 subject，
   仅目标绑定被清除，另一站全行保持不变；注入失败后用户行及 12 条 claim 全部回滚。
4. 通过真实渠道控制器修改多密钥策略，验证换行/JSON 密钥、状态、额度、路由能力及其他字段保留，
   正常追加操作审计而不泄漏密钥。

两台临时实例已正常关闭。本批未改变上述数据库实现，因此后续纯协议转换修复不改变此迁移验收对象。
未连接生产数据库、未使用生产备份，也未实测 MariaDB；结论限于覆盖的版本和测试数据。
