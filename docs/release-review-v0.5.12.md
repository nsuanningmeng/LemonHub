# v0.5.12 发布复审

复审基线为 v0.5.11 的 `012a5f8562d333ab4eb25745e06b64d05c7e26bf`。范围包括本轮全部生产代码、回归测试、依赖锁、Dockerfile 和发布工作流，并重新检查调用链，而不只复用分批审查结论。

## 发现并修正的问题

1. **缓存写入别名在部分结算路径丢失。** 原始 Responses 用量快照恢复为结算用量时，没有将 `input_tokens_details.cache_creation_input_tokens` 补入统一明细；图片和 Responses compact 的手工映射也遗漏该字段。修复后继续采用现有输入包含缓存的语义，多别名取最大值，保留已经归一化的字段。回归从真实 JSON、公开协议转换和图片 JSON/SSE 处理进入计费边界，覆盖别名并存、负数、已有明细和流式请求收到 JSON 的情况。示例中输入 1,000、输出 20、缓存读取 100、写入 300，指定倍率下应计 1,005，而遗漏写入的旧路径计 930。
2. **开发调试工具要求的依赖版本不匹配。** 上游 `@tanstack/react-query-devtools` 5.105.0 要求 `@tanstack/react-query` ^5.105.0，本地运行库为 5.101.2。取消这项同步，保留 Devtools 5.101.2；删除由新版 Devtools 单独引入的依赖，其余包和安全覆盖规则不变。冻结安装和类型检查通过。
3. **长正则在批量条件处理中重复编译。** 超过 4 KiB 的表达式有意不进入全局缓存，但仍应在同一次请求内复用；恢复请求内复用并在表达式变化时重新编译。保留共享 LRU 的 256 项、单表达式 4 KiB 保留上限，以及缺失字段时的惰性验证。

## 其他复审结论

- 渠道亲和失败后的优先级偏移不增加重试预算，跨组后清除偏移；选中组的价格和权限继续经过已有流程。
- 日志 writer 在轮转锁内解析并写入当前文件，保留路由模板和敏感信息保护；zstd 超限继续返回 413。
- HTTP/2 探测默认关闭；时长转换有上限，代理、分片、HTTP/1、SSRF 防护及响应头超时继续有效。
- 启动时提前注册 SIGTERM 不改变原有账务排空顺序和 120 秒预算；失败仍报告异常退出，不伪装为成功停机。
- 前端定价分类使用已有解析器，不执行表达式；侧栏仍受管理员边界约束，验证码保存失败会停止后续写入。
- 未引入实验性插件、额外路由、插件数据库表或新的 JSON 引擎。相对 v0.5.11 没有 model、数据库驱动、表结构、迁移或 Compose 数据卷改动。

## 验证和发布边界

修复分为三个可独立审查的提交：Devtools 兼容回退 `3fb6a689f`、请求内正则复用 `ac2ca7583`、缓存别名完整映射 `648289cba`。最后一项经过修复作者验证及独立复测（6 个顶层测试、含子用例 27 项，无失败或跳过）；服务、OpenAI/AWS/xAI、controller 及独立 relaykit 转换测试通过。正则全包、定向 race 和另一位审查者的独立定向验证通过。未把性能测量改为依赖计时的回归断言。

分批全量验证及 MySQL 8.2 候选镜像演练见 [同步记录](upstream-sync-2026-11-02.md) 和 [数据库报告](mysql82-upstream-sync-2026-11-02.md)。发布复审的新增修正另做针对性回归及独立复核，并以包含全部修正的同一提交运行完整 CI；旧候选镜像的测试不能替代正式镜像验证。

发布遵循现有工作流：先推送审查分支运行 CI，成功后快进 main 并推送 v0.5.12 标签；Linux、macOS、Windows 和 Electron 产物全部就绪后才公开 Release。Docker 工作流分别构建 amd64/arm64，按不可变摘要合并版本镜像，验证来源提交后更新 latest。正式镜像还需按摘要在独立 MySQL 8.2 测试卷上验证旧版本升级、重复启动、同卷重建和备份恢复。运行结果和正式镜像摘要补充到该版本的 Release。

本轮不部署生产服务器。数据库结论只覆盖已执行的隔离样本及报告列出的升级条件。

## 托管 macOS runner 容量不足的恢复发布

标签对应的原 Release 工作流两次都在分配 macOS runner 时失败，没有执行 macOS 构建步骤。Linux、Windows、Electron 和 Docker 均已成功。新增手动的一次性 [恢复工作流](../.github/workflows/recover-v0.5.12.yml)，在 Ubuntu 使用相同 Go 1.26.10、Bun 1.4.4、完整前端和原有 CGO=0 参数交叉编译 Darwin 两种架构；原流程也没有 macOS 原生运行测试或 Apple 签名步骤。

恢复流程将应用源码固定为 `86ae810bae8519aef3e20f28b65f4893f5b79ea1`，不移动 v0.5.12 标签。原平台产物按固定 artifact ID、ZIP 摘要、文件校验和及原签名验证后复用；新产物同时保留真实恢复工作流证明及包含应用源码、恢复提交、全部产物和完整发布说明摘要的签名清单。两类身份不能混称为同一个源码提交。

工作流、校验脚本及权限经过独立审查，actionlint、11 项校验测试及 7 项独立边界测试通过。仅允许原第二次尝试完全结束且确认是构建前的容量失败时运行；不会覆盖已公开版本或不同的草稿产物。全部文件和签名验证成功后先创建完整草稿，再发布。此流程不支持只重跑发布 job；若中断，必须完整重跑/重新手动触发，已有不一致草稿需另行核查，不自动删除或覆盖。
