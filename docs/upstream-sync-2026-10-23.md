## Go 安全修复

[Go 官方公告](https://groups.google.com/g/golang-announce/c/66pojueaQek)与 [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)确认：CVE-2026-111943 由 Go 1.26.10 / 1.27.3 修复。`crypto/x509` 拒绝包含特定已不可信 SPKI 的证书链。二进制必须使用新工具链重新编译；只更新操作系统 CA 包不能替代此次修复。

两份 Dockerfile 均固定官方多平台构建镜像：

```text
golang:1.26.10-alpine@sha256:27f2d3b83cfc5803c8078f8e730af0f7c431bf067afaec8f60a36fb763187cba
```

已拉取固定镜像并实际验证 `go version go1.26.10 linux/amd64`。本地官方工具链归档经过 SHA256 校验，标准库 `TestGoVerify` 回归通过。CI、发布和 Electron 均从 `go.mod` 读取版本。未新增绕过 TLS 校验的兼容方案；遇到被拒绝证书链应更换上游证书。已有管理员主动跳过验证的配置不会获得常规证书验证保护。

## 数据与行为兼容

- `quota_data` 只追加 `cache_read_tokens`、`cache_creation_tokens` 两个 `BIGINT DEFAULT 0` 字段；既有业务行、列和索引不应改变。保留批次事务、已知回滚重排及提交结果不确定时禁止盲目重放的机制。
- 上述“两列”是相对 `db0a58cf0` 的上游同步差异。由更早的 `0fb01c80b` 升级还会执行本仓库已有的性能统计 identity hash/索引迁移；已另外运行旧 schema 的 MySQL UTF-8、GBK 历史保留测试，不能把这部分省略为“两列升级”。
- 原生任务轮询允许同源跳转，拒绝跨源跳转及 HTTPS 降级；需要跨源跳转的配置应直接指向最终可信上游地址。客户端头不持久化，后台只解析静态值和任务实际 `{api_key}`。
- 不覆盖已保存的价格和表达式。新请求的缓存计费修正可能改变费用：未显式定价的 Claude 1h / OpenAI 12h 写入按各自短期价的 1.6 / 2 倍归入；没有短期价则由输入价承接。显式 12h 零价必须保持零价。`len` 始终使用未加权的真实上下文总量，具体规则见 [表达式文档](../pkg/billingexpr/expr.md)。
- Compose 的项目/服务名称、MySQL 8.2 示例、数据卷与应用挂载保持不变。实际部署继续使用自己的 MySQL 配置，不能以仓库默认 PostgreSQL 示例覆盖。

### 约 800 GB、单实例、一分钟中断窗口

隔离环境数据保留测试不等于这一生产窗口已经通过。当前没有连接生产库，尚未确认 `quota_data` / `channel_perf_metrics` 的实际大小、行格式、既有索引、历史 INSTANT 列变更次数及长事务情况。

MySQL 8.2 通常可以即时追加这两个统计列，但当前 GORM 迁移没有强制 `ALGORITHM=INSTANT` 或设置专门的 metadata lock 超时。由 `0fb01c80b` 起升级还需要性能统计身份回填及索引迁移，耗时与该表规模相关。应用现有优雅停机期限为 120 秒，Docker 宽限为 130 秒，本身也不能给出 60 秒的最坏情况承诺。不能通过临时缩短期限来绕过尚未完成的账本刷新。

因此，这次结论是代码与隔离 MySQL 8.2 验证通过后可供部署评估，**尚未验收 800 GB 单实例一分钟内升级**。上线前仍须对生产做只读表结构/规模/长事务检查，并在真实规模的克隆库测量迁移和停机刷新时间；超出窗口就取消该窗口内的升级，重新安排迁移方式。800 GB 备份恢复也不应被当作一分钟内可完成的回退方案。本次未操作生产、推送代码、发布 release 或部署镜像。

| 范围 | 拦截的问题与最终处理 |
